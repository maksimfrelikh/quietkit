# Deploy

Static site. `npm run build` writes `dist/`; nginx serves it straight from
`/var/www/quietkit/dist`. No Node process, nothing to restart except nginx when its config
changes. Host: laptop-server, `quietkit.frelikh.dev`, TLS from the existing `*.frelikh.dev`
wildcard certificate.

## First-time setup (once, needs sudo)

```
sudo -v \
  && sudo git clone git@github.com:maksimfrelikh/quietkit.git /var/www/quietkit \
  && sudo chown -R $USER:$USER /var/www/quietkit \
  && cd /var/www/quietkit && npm ci && npm run build \
  && sudo cp deploy/nginx.conf /etc/nginx/sites-available/quietkit \
  && sudo ln -sf /etc/nginx/sites-available/quietkit /etc/nginx/sites-enabled/quietkit \
  && sudo nginx -t && sudo systemctl reload nginx
```

`npm ci` fetches `stark-ui-kit` over `git+ssh`: run this in an interactive session where the
TPM SSH agent is available (or export `SSH_AUTH_SOCK=/run/user/1000/ssh-tpm-agent.sock`).

## Updating a running deploy

```
cd /var/www/quietkit && git pull --ff-only && npm ci && npm run build
```

No sudo, no restart: nginx reads the new files on the next request. Hashed assets under
`/_astro/` change name on every build and are cached for a year; HTML is `must-revalidate`.
The window between the build deleting old assets and the new HTML being served is the
build itself (a few seconds); acceptable for now, an atomic `dist` swap is a later nicety.

If the commit touched `deploy/nginx.conf`, also:

```
sudo cp /var/www/quietkit/deploy/nginx.conf /etc/nginx/sites-available/quietkit && sudo nginx -t && sudo systemctl reload nginx
```

## Verify

```
curl -sI https://quietkit.frelikh.dev/ | grep -iE '^(HTTP|content-security|strict-transport)'
curl -s https://quietkit.frelikh.dev/tools/nbsp | grep -c 'http-equiv="content-security-policy"'   # 1
curl -s -o /dev/null -w '%{http_code}\n' https://quietkit.frelikh.dev/nope                          # 404
```

The CSP that matters is in the page `<meta>` (generated by Astro), not in the nginx header,
which carries only `frame-ancestors`. See CLAUDE.md § CSP.

## Design-system dependency

`stark-ui-kit` is pinned by commit in `package.json`; its CSS is bundled at build time, so
nothing extra is deployed. Changing the kit: push the kit, bump the sha here, `npm install`,
`npm run verify && npm run e2e`. Never `file:../stark-ui-kit` (npm caches it by version and
edits stop reaching the build).
